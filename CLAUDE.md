# CLAUDE.md — meals_client

The Meals 2.0 client monorepo (npm workspaces): a polished web DOM app and a
native Expo app sharing a non-view core. A new git repo, created by moving the
former `meals_client_v2` in as `apps/web`. Read `../SPEC_MOBILE.md` for the
client architecture and the reasoning; `../SPEC.md` for product direction.

## Layout

- `apps/web` — Vite + React DOM client (`react-router-dom`, `theme.css`). The
  original `meals_client_v2`, moved in unchanged; its Playwright e2e is in
  `apps/web/e2e`.
- `apps/native` — Expo / React Native app (`expo-router`), Android + iOS. See
  `apps/native/CLAUDE.md` for the device run/update/debug workflow.
- `packages/core` — shared and view-agnostic: design tokens (from web's
  `theme.css`), TanStack Query hooks (`useWeekPlans` and the other API-backed
  reads/mutations), and auth orchestration with per-platform adapters. Both apps
  consume it; neither owns server-state logic.

Contract DTOs come from `@elliotJHarding/meals-api` (generated by `meals_model`),
consumed by both apps as today.

## Build / typecheck

- Web: `cd apps/web && npm run build` (tsc + vite); e2e via Playwright in `apps/web/e2e`.
- Native: see `apps/native/CLAUDE.md`. `npm run typecheck` (`tsc --noEmit`) runs per package.

## Running the web client

`cd apps/web && npm run dev`, then open http://localhost:5173. Needs:

- `meals_server` on `:8080` (the API the client calls).
- `VITE_GOOGLE_CLIENT_ID` in `apps/web/.env.development.local` (required for
  login; Vite's env root is `apps/web`, not the monorepo root).

Port 5173 is pinned with `strictPort` in `vite.config.ts` — it is the only
localhost origin authorised on the Google OAuth client, so Vite fails rather
than falling back to another port. Consequences:

- The original `meals_web_client` (v1) also wants 5173; don't run both. To run
  both, authorise `http://localhost:5174` in the Google Cloud Console.
- A `Port 5173 is already in use` failure can be a **stale Vite dev server
  orphaned by the monorepo move** — a process still running from the old
  `meals_client_v2/` path (now `apps/web`), squatting on 5173 and serving a
  broken page. Find it with `lsof -nP -iTCP:5173 -sTCP:LISTEN`, confirm its
  command points at the absent `meals_client_v2/`, kill it, then start `dev`.
